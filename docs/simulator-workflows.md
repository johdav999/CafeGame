# Stage 9: task workflows and staff scheduling

Each browser order creates three linked barista tasks: collect supplies (half a second after reaching the supplies), prepare using the existing production job, then walk to the hand-over point. Serve becomes available only after the barista and customer reach their points. Preparation consumes ingredients once, through the production runtime.

The barista has barista and cleaner roles. Service tasks have priority 20; table cleaning has priority 5. Allocation uses priority then FIFO task IDs and does not preempt active work automatically. A guest's dirty seat remains reserved until the guest has left and a one-second cleaning task finishes. Used cups and a cleaning cloth make cleanup visible. Staff navigation reuses the engine WaypointGraph/PathFollower on authored corridors.

Take staff break interrupts staff tasks and preserves timed progress. Customer patience, seated time and already-running machine brewing continue. Resume staff shift assigns fresh task tokens and rebuilds movement. Resuming preparation checks the actual production state and cannot commit inputs twice. Global Pause still freezes the whole simulation.

The optional portable TaskBoard helper supplies task dependencies, role matching, priorities, staff shift windows, timed/external work, interruption, cancellation propagation and validated typed snapshots. It owns no paths, actors, effects, application clock or production inventory. Shift calendars, wages and staff skills remain future work. Native simple-host methods retain explicit immediate arrival/seating; browser input enforces the full task gate.

Cafe save envelope 3 includes task/worker state, remaining work, staff availability, service task IDs and dirty-seat ownership alongside wallet, spatial claims and core bytes. Candidate load validates cross-system references before publication. Navigation tokens are transient; restore uses fresh epochs/tokens and safe reconstructed positions. Cafe formats 1 and 2 are migrated; Runtime core schema remains 1. The existing localStorage slot is retained.

Tests cover priority/FIFO allocation, dependency barriers, role restrictions, shift start/end boundaries, interrupted remaining work, stale arrivals, cascade cancellation, retirement, invalid snapshot preservation and full cafe workflow/cleanup restore.
