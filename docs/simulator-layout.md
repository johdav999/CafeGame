# Stage 13: placement and layout

Open **Build and layout**, then **Close for layout**. Waiting guests leave; the current order can still be served, seated guests finish, and table cleaning completes. Editing becomes available when the cafe has no guests, active service or tasks. Reopening allows new guests and brewing again. Closing alone does not pause the clock or stop wages; the staff-break and global-pause controls retain their existing behavior.

Select one of the two stable table slots. Use the coordinate fields or click the floor plan to choose a lower-left footprint anchor. Coordinates snap to half-metre cells; rotation uses quarter turns. The plan shows both tables, fixed obstacles and a preview. Brass squares mark front access cells. Native C++ validation controls the preview and the command, so an invalid or stale request cannot move furniture or spend money. Keyboard-accessible fields provide the same operations as the pointer map.

Move and rotate are free. A complete table set costs 6.00 to buy and sells for 3.00. Initial furniture is already owned. Repeated selling cannot create another payment; failed placement, duplicate buying, insufficient available cash or ledger overflow preserve layout, claims and cash. Purchase and sale postings appear in finances and saved ledger history. Wages owed take priority over purchases. Sold tables disable their stable seat index. With no tables, guests use takeaway service and leave after receiving coffee.

The footprint includes a table and both chairs: 2 by 4 metres before rotation. Validation rejects room overflow, overlapping furniture/fixed obstacles, less than one cell between furniture, blocked interaction cells and disconnected required destinations. All table access cells, queue/waiting positions, entrance, counter and staff work points must remain connected on the four-neighbour free-cell grid. The room is 24 by 20 half-metre cells with authored fixed counter, storeroom and plant obstacles.

Accepted edits rebuild a WebEngine WaypointGraph from walkable cell centres. Guests and staff continue to use engine PathFollower and CharacterMotorComponent, existing arrival tokens and task/core guards. Seating and cleanup target the moved table's access cell. Scene table/seat/cup geometry follows the saved transform. Editing requires an empty floor, so no live path or occupancy claim is silently relocated. Load clears transient navigation and reconstructs paths and actors. This is conservative axis-aligned grid placement; arbitrary shapes, free-angle rotation, multilevel construction, drag handles and crowd collision avoidance remain outside this stage.

The optional portable `engine/simulator/layout.hpp` supplies GridLayout, Placement, GridCell/GridRect, finite snapping, rotated footprints/access and candidate validation. It owns no scene, actor movement, money, clock or storage. `OccupancyPool::setEnabled` accepts one 0/1 byte per stable point; claimed points cannot be disabled, enabling promotes waiting owners, and failed edits preserve holders and tokens. Compact queues require all points enabled. The game owns prices, definitions, masks, navigation projection and cross-system coordination.

Cafe envelope 7 appends open/closed state and two table records. Candidate load validates exact game definitions, footprints, reachability, enabled seat claims and the initial-two-plus-purchases-minus-sales furniture identity before publishing anything. Formats 1-6 migrate to the default two tables and an open cafe. Older envelopes cannot contain furniture transactions. Core snapshot schema 1, renderer pin and localStorage slot remain unchanged. The diagnostic console adds `close` and `layout ACTION ID X Z ROTATION`, with grid-cell coordinates and actions 0 move, 1 sell, 2 buy.

Generic checks cover finite snapping, rotations, atomic invalid edits, disconnection and enabled occupancy masks. Game checks cover the close/drain gate, moved-layout restore, money conservation, repeated commands, unavailable seats, takeaway, corrupted saves and schema-6 migration. Browser acceptance exercises preview rejection, actual moves/rotation, buying/selling, reload, and service/seating/cleanup along rebuilt routes. Set `CAFE_LAYOUT_ONLY=1` when running `tools/browser-smoke.cjs` to run just the layout scenario; the default includes the full service, supply, economy and quality regression flow.
